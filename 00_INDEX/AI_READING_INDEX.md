## 8. Candidate / established separation

Always preserve the distinction among:

```text
Established
Candidate
Working
Unverified
Historical
```

A later file can supersede a definition without proving the earlier definition was false.

## 9. Temporal rule

Never use file date as the sole authority for theory status.

Use:

```text
Date = formation history
Status = current research position
```

Both must be retained.

## 10. Reading procedure

```text
1. Identify file metadata
2. Identify current / historical / active status
3. Read current theory baseline
4. Read core candidate baseline
5. Read active research relevant to the query
6. Consult historical versions only for lineage or contradiction
7. Consult construction_lab only when experimental evidence is relevant
8. Preserve unresolved conflicts rather than silently merging them
```

## 11. Retrieval rule

When answering a question about Construction:

- prefer current theory for current definitions;
- prefer dated records for formation history;
- prefer active research for unresolved questions;
- prefer experimental files for empirical / engineering claims;
- never derive a current definition solely from an old implementation;
- never promote a research candidate into established theory without explicit status change.

## 12. Current non-claims

Do not infer that Construction:

- has a unique MCS;
- has a unique representation form;
- is a complete theory of human mind;
- is a completed AI architecture;
- is already empirically validated in all respects;
- automatically reduces token or computational cost;
- automatically improves model accuracy;
- grants AI independent governance authority.
