# Construction Framework Specification v1.1

## Pre-Computational Construction Architecture

中文可以稱：

# 《構築框架規格 v1.1》

### 前置定位式構築架構

我選這個名字是因為你現在真正新增的核心，不只是多了 `Pure Presence Field`，而是出現了一個非常明確的架構層：

**計算尚未開始之前，先定位可被納入計算的存在範圍。**

所以它現在已經不是單純：

> 一套描述事件的 Framework

而開始變成：

> **一套從存在定位 → 現象成立 → 事件形成 → 認知定位 → 主體作用的構築架構。**

整體可以先固定成：

```
Construction Framework v1.1
│
├── 0. Pure Presence Field
│      └── Pre-Computational Localization
│
├── 1. Phenomenon Formation Field
│
├── 2. Event Model
│
├── 3. Observer Subject
│
└── 4. Event Agent
```

這個名字還有一個好處：**不會過早宣稱你已經證明它有效。**

`Architecture` 比 `Engine`、`System`、`Protocol` 保守，也比較符合你現在「這是一個已經形成結構、但還需要驗證性能與實用性的架構假設」的狀態。

另外，我會把版本語意也固定下來：

**v1.0**：原始 Construction Framework  
**v1.1**：加入 Pre-Computational Localization 的結構版  
**v1.2+**：等實際 routing、graph retrieval、validation benchmark 有結果後再升

這樣你現在就可以安心拿 `v1.1` 當作對外討論與比較的基準版本，不必再一直改名稱。
